# PowerGym Production Operation Checklist

Use this checklist for every production deployment. It is designed to make releases repeatable, auditable and reversible.

## 1. Before the deployment window

1. Confirm the release ZIP/commit and patch version being deployed.
2. Confirm the target environment variables are loaded from the production secret store, not from a committed `.env` file.
3. Confirm database credentials have permission for migrations and backup export.
4. Confirm `mysqldump` is available on the machine or CI runner that executes `npm run db:backup`.
5. Confirm there is enough disk space for at least one full SQL dump plus 30 days of retained backups.
6. Notify users/admins of the maintenance window if migrations are expected to lock large tables.

## 2. Preflight

Run:

```bash
npm ci
npm run deploy:preflight
npm run verify:ci
npm run db:integrity
```

The deployment should not continue if `deploy:preflight` reports a **critical** failure. Warnings should be reviewed and either fixed or explicitly accepted for the deployment window.

## 3. Backup before migrations

Run:

```bash
npm run db:backup -- --label=predeploy
```

Record the generated SQL file path in the deployment notes. The backup command uses `mysqldump` with `--single-transaction`, `--routines`, `--triggers` and `--events`.

Dry-run example:

```bash
npm run db:backup -- --dry-run
```

## 4. Apply migrations

Run:

```bash
npm run db:migrate
npm run db:integrity
```

If integrity returns critical findings, stop and decide whether to run the safe repair scripts or roll back.

## 5. Deploy application artifact

Build and start the application using your hosting platform. For a local/Docker-style deployment:

```bash
npm run build
npm start
```

## 6. Post-deploy smoke tests

Run:

```bash
npm run deploy:smoke -- --base-url=https://your-domain.example
```

Optional authenticated database smoke check:

```bash
DEPLOY_SMOKE_AUTH_TOKEN=<token> npm run deploy:smoke -- --base-url=https://your-domain.example --include-db
```

## 7. Manual smoke checklist

Verify the following from the UI:

1. Login as admin succeeds.
2. Dashboard opens.
3. Members screen loads and can search/filter.
4. Generate e-card token works for an active member with a future expiry date.
5. Reports screen opens and a filtered PDF downloads.
6. Accounting, HR, Group Classes and Private PT screens load.
7. Settings > Security Center shows data.
8. Settings > Data Integrity Center shows checks.
9. Password reset request returns a generic success response and delivery is logged.
10. `/api/health` returns `ok` or expected degraded state during planned database work.

## 8. Rollback plan

Rollback has two parts: application and database.

### Application rollback

1. Redeploy the previous working ZIP/image.
2. Keep the database unchanged if the migration was backward-compatible.
3. Run smoke tests against the previous version.

### Database rollback

Only restore the predeploy SQL backup when the application rollback is not enough or the migration damaged data.

1. Put the application in maintenance mode or stop traffic.
2. Confirm the exact backup file generated by `npm run db:backup -- --label=predeploy`.
3. Restore using your managed provider workflow or MySQL CLI.
4. Re-run `npm run db:integrity`.
5. Restart the previous application version and run smoke tests.

## 9. After deployment

1. Review Security Center alerts for the first 30 minutes.
2. Review password reset delivery failures.
3. Review database health and backup status.
4. Save the deployment notes, backup path, build ID and smoke test output.
5. Schedule any warning-level data integrity repair work outside peak hours.


## 10. Daily membership reconciliation

The integrity check and reconciliation command share one eligibility rule across legacy
`member_subscriptions` and V2 `affiliations` / `subscriptions`. Start and end dates
are inclusive.

Preview without changing data:

```bash
npm run db:reconcile-memberships
```

Apply after reviewing the candidates:

```bash
npm run db:reconcile-memberships -- --apply
npm run db:integrity
```

On Linux, `powergym-membership-reconciliation.timer` runs the apply mode daily at
00:10 with a randomized delay of up to two minutes. The timer is persistent, so a
missed run is executed after the host starts. Each status change is recorded in
`audit_logs` with action `member_automatically_deactivated`.
